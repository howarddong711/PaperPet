# PaperPet 0.5.2 云同步方案设计书

## 1. 文档信息

- 目标版本：PaperPet 0.5.2
- 状态：本机实现与双数据库模拟已完成，真实双设备 Zotero 验收待进行
- 目标平台：Zotero 10.x，Windows、macOS、Linux
- 同步方式：复用用户已有的 Zotero 同步，不新增 PaperPet 云服务

## 2. 目标与非目标

### 2.1 目标

让用户在使用同一个 Zotero 账号的多台设备上，看到一致的 PaperPet 阅读历史、笔记编辑统计、会话修正状态和可选的 PaperPet 设置。

同步必须满足：

1. 断网时可以继续本地阅读和记录。
2. 网络恢复后可以最终一致地合并两台设备产生的数据。
3. 同一条会话不能因为两台设备合并而重复累计。
4. Zotero 同步失败时不影响阅读识别和本地报告。
5. 不上传 PDF 全文、原生笔记正文、划线内容或输入内容。

### 2.2 非目标

- 不直接同步 PaperPet 的 SQLite 数据库文件。
- 不实现独立的 PaperPet 账号、服务器和实时推送服务。
- 不替代 Zotero 对文献、附件和原生笔记的同步。
- 不保证实时同步；Zotero 同步完成前，另一台设备可能暂时看不到最新记录。
- 不把本机窗口位置、临时 UI 状态和绝对路径当作跨设备设置。

## 3. 关键约束

PaperPet 当前数据库位于 Zotero 数据目录下的 `paperpet/paperpet.sqlite`。Zotero 同步的是它认识的库数据和附件，不会安全地把这个 SQLite 文件当作普通文件合并。SQLite 的 WAL、锁和并发写入也不适合通过文件同步解决，因此本地数据库必须继续保持每台设备独立。

同步数据需要放入 Zotero 可同步的数据载体。0.5.2 为每台设备保留独立的 Zotero note；小快照直接写入，超过安全长度时写入多个短数据块 note 和一条索引 note。旧版单 note 的隐藏注释和超长 V2 note 仍可读取；本机超长 V2 note 会在下次写入时改写为短索引。每台设备只修改自己的 note，因而两个设备同时离线写入时不会争夺同一 Zotero 条目。note 属于 Zotero 数据同步，与 PDF 附件选择 Zotero 存储或 WebDAV 无关。

## 4. 总体架构

```text
本机阅读识别
      |
      v
本机 PaperPet SQLite  ---- 本机报告/角色包/设置
      |
      | 生成同步快照（不上传正文）
      v
每台设备各自的 PaperPet Sync note（短笔记或分片加索引）
      |
      v
Zotero 同步服务
      |
      v
另一台设备发现 note 变化 -> 校验 -> 合并到本机 SQLite -> 重建汇总
```

同步适配器分为四层：

1. `SyncIdentity`：保存本机设备 ID 和稳定的库身份，本机专用，不参与覆盖。
2. `SyncSnapshot`：把可同步的原始记录序列化为版本化数据。
3. `ZoteroNoteCarrier`：查找所有设备的 note，仅写入本机设备的短 note 或分片，并兼容读取旧版单 note。
4. `SyncMergeService`：校验快照、去重、合并冲突、写入本地数据库并重建派生表。

## 5. 同步数据边界

### 5.1 同步的数据

- 已结束或定期刷新的 `reading_sessions` 原始会话。
- `semantic_events` 中的动作事件，遵守现有 90 天保留策略。
- 会话的排除、恢复和软删除状态。
- PaperPet 用户设置中标记为可同步的部分。
- 同步格式版本、导出设备、更新时间和内容哈希。

### 5.2 不同步的数据

- `daily_item_stats`、`item_totals`：它们是派生数据，导入原始会话后本地重建。
- `growth_ledger`：避免重复发放成长记录；同步后从会话和批注统计重建或改为幂等写入。
- PDF、EPUB、快照和原生笔记正文：由 Zotero 自身同步。
- 宠物位置、窗口句柄、当前报告标签页和临时诊断状态。
- `install_path`、临时目录和其他本机绝对路径。
- 本机 `deviceID` 本身。每台设备必须保留独立身份，不能被远端设置覆盖。
- 同步开关和角色包文件；两台设备可各自选择是否同步并独立安装角色包。

## 6. 跨设备身份

当前阅读记录使用数字 `libraryID`、条目 key 和附件/笔记 key。数字 `libraryID` 只适合本机数据库，不能假设在不同 Zotero 配置中永久一致。0.5.2 应增加稳定的 `libraryRef`：

- 用户库：`user`
- 群组库：`group:<groupID>`
- 条目身份：`libraryRef + itemKey + sourceKey`

旧记录保留原字段以兼容报告和备份；同步导出时生成稳定引用，导入时映射回本机 `libraryID`。找不到对应群组库时，当前实现会跳过该群组记录并保留在远端 note，等待该群组库在本机可用后再次导入。

## 7. 同步格式

同步 note 中使用一个带版本的 JSON 封装。示意结构如下：

```json
{
  "format": "paperpet-sync",
  "schemaVersion": 1,
  "exportedAt": 0,
  "exportedBy": "device-uuid",
  "contentHash": "fnv1a:...",
  "sessions": [],
  "events": [],
  "settings": []
}
```

### 7.1 会话记录

每个会话使用不可变 UUID。会话由产生它的设备写入，定期刷新的累计值带有 `updatedAt` 和 `updatedBy`。同一 session ID 的多个版本按 `(updatedAt, updatedBy)` 进行确定性选择，不能简单按导入顺序覆盖。

### 7.2 会话修正

排除、恢复和软删除更新原会话的 `excluded`、`deleted`、`updatedAt` 与 `updatedBy`。同一 UUID 的会话按 `(updatedAt, updatedBy)` 选择一个确定版本，应用后重建 `daily_item_stats` 和 `item_totals`。

### 7.3 事件去重

语义事件使用自身 UUID。导入使用 `INSERT OR IGNORE`，同一个事件无论同步多少次都只能计数一次。超过 90 天的事件可以从同步快照中裁剪，但会话累计统计不能丢失。

### 7.4 设置和角色包

可同步设置使用键、值、更新时间和设备 ID，出现并发修改时采用确定性的最后写入规则。同步开关及设备 ID 为本机专有，角色包文件与本机安装路径不参与同步。

## 8. 同步流程

### 8.1 本机写入

1. 阅读会话按现有流程写入本机 SQLite。
2. 事务成功后标记同步游标为 dirty。
3. 以防抖方式生成同步快照，不在每个输入事件后写 Zotero。
4. 小快照写入本机设备的短 note；大快照先写变化的数据块，最后更新索引。Zotero 后续上传这些 note。

### 8.2 远端变更

1. Zotero item 通知或启动时扫描专用 note。
2. 读取所有 PaperPet note，校验格式、字段和内容哈希。
3. 在本地数据库事务中合并会话、事件和设置。
4. 仅在原始会话或事件有变化时重建派生汇总，并在需要时重新发布合并结果。
5. 更新本机写入时间、发现的其他设备数和会话数；失败时保留本地数据并显示错误。

### 8.3 防止回环

同步写入前比较排序后的数据内容；仅时间戳变化不会重复写入。同一会话或事件的重复副本不会增加汇总，因此两台设备交换 note 后最终收敛。

## 9. 隐私、容量和用户体验

- 云端载体中可能包含文献标题、条目 key、阅读时间和行为类型；设置页必须在启用同步前明确提示。
- 不上传正文和笔记内容，但标题仍属于用户的阅读元数据。
- 当前同步原始会话和本机保留期内事件；超出单条笔记安全长度时按约 12,000 个编码字符分片。未变化的数据块不重复保存，旧数据块可复用。压缩与更大规模数据载体属于后续工作。
- 另一设备在所有分片到齐且长度、哈希校验一致后才导入；分批到达期间保留已有本地记录并自动重试。
- 设置页提供：启用同步、从 Zotero 读取、写入本机 Zotero、本机写入时间、发现的设备数、两端会话数，以及另一设备已包含多少本机会话的最新版本。插件启动、同步笔记变化及每 60 秒自动读取已到达本机的笔记；手动读取还会请求 Zotero 执行数据同步，但按钮返回不代表云端下载已完成。
- 报告可按本机、其他设备或指定设备筛选，并列出各设备的会话数、时长和最近活动；单篇详情显示全部设备的会话来源。
- 删除 Zotero 同步 note 不会自动删除本地记录；重新执行本机写入可重建本机 note。

## 10. 失败与恢复

- Zotero 账号未登录或数据同步关闭：本机 note 仍可写入，但界面不宣称云端已完成；用户应在另一台设备核对接收结果。
- 尚未收到其他设备 note：状态为 `waiting`，下次 Zotero 条目通知、定时读取、启动或手动读取时重试。
- 格式错误、版本过新、哈希不匹配：状态为 `error`，保留本地数据并提示重试或检查 note。
- 合并失败：回滚本地事务，保留原数据库和远端快照，不删除任何记录。
- 角色包未安装：同步统计继续可用，在新设备手动添加角色包。

## 11. 验收标准

0.5.2 至少必须通过：

1. 单设备离线阅读后恢复 Zotero 同步，记录能上传且不重复。
2. 两台设备离线阅读同一文献后合并，报告总时长等于两台设备有效记录之和。
3. 两台设备对同一会话做排除/恢复时，结果可确定且不会产生重复汇总。
4. 同一同步快照重复导入十次，报告数值不变化。
5. 旧版本地数据库和 0.5.1 备份仍可正常打开和导入。
6. Zotero 同步不可用或账号未登录时，界面不宣称云端成功，阅读和本地报告不受影响。
7. 删除或损坏同步载体后，本地数据仍完整，且可以用手动备份恢复。
8. 不会同步 PDF、原生笔记正文或用户输入内容。
