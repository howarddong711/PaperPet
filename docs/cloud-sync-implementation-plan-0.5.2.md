# PaperPet 0.5.2 云同步实施计划书

## 当前进度

- 已完成：schema 3 迁移、原始会话与事件幂等合并、按设备分开的 Zotero note、旧版单 note 读取、超长笔记分片及本机 V2 载体迁移、本机同步开关、手动读取和写入、通知与定时自动读取、报告来源筛选及设置页可核对的设备与会话计数。
- 已验证：两份隔离 SQLite 的离线写入、双向交换、重复同步和会话排除；自动化测试、类型检查与构建。
- 发布前仍需：在两台真实 Zotero 10 设备上安装同一测试 XPI，完成 Zotero 数据同步并核对报告。`0.5.2` 版本号目前用于测试构建，不表示已发布。
- 后置：角色包文件同步、超大快照压缩或专用载体、Zotero 服务器确认状态。当前界面只报告本机 note 写入和另一设备 note 是否已被读取。

## 1. 实施原则

- 使用 Zotero 数据同步中的独立 note 作为载体，并在真实设备上完成最终验证。
- 保持本地 SQLite 为运行时事实来源；云端只承担可合并的同步快照。
- 同步阅读会话、动作事件和可同步设置；角色包文件后置。
- 所有导入都必须可重试、幂等、可回滚。
- 不在真实用户数据库上做破坏性实验，使用内存 SQLite 和隔离 Zotero 测试配置。
- 0.5.2 期间不引入自建服务器、账号系统或第三方云 SDK。

## 2. 阶段划分

### 阶段 0：Zotero 载体技术验证

任务：

- 确认 Zotero 10 中创建独立 note、写入设备标记与读取内容的可用 API。
- 确认 Zotero `Notifier` 能在 note 到达本机后触发重新读取。
- 验证 Zotero 数据同步开启和关闭时的实际表现，以及多设备同一账号下的可见性。

输出：

- `ZoteroNoteCarrier` 最小原型。
- Zotero 10 Windows 双配置文件手动验证记录。
- API 限制、权限和失败场景清单。

门槛：两台真实设备不能稳定交换 note 时，不发布 0.5.2 云同步版本。

### 阶段 1：同步身份和数据库迁移

任务：

- 增加 schema 3（暂定）和迁移测试。
- 本机保留设备 ID 和同步开关，运行时跟踪本机写入时间、其他设备可见性与错误摘要。
- 增加稳定 `libraryRef` 的生成、旧记录映射和未找到条目的保留逻辑。
- 将设备 ID 与可同步设置分离，防止一台设备覆盖另一台设备身份。
- 为会话及其排除、恢复操作增加 `updated_at`、`updated_by` 字段。

验收：0.5.1 数据库升级后原有阅读记录、设置和角色包不变；迁移重复执行不会增加列或记录。

### 阶段 2：纯数据快照和合并服务

任务：

- 新建纯 TypeScript `SyncSnapshot` 类型和序列化器。
- 只导出原始会话、语义事件和可同步设置。
- 实现格式版本、哈希和字段校验；载体层将超长快照拆成短笔记。
- 实现按 session/event UUID 的幂等导入。
- 实现确定性冲突规则，拒绝按数组顺序覆盖。
- 会话或事件变化后重建日报和文献总计，明确区分派生表与原始表。

测试：

- 相同快照重复导入。
- 两台设备交错生成会话。
- 同一会话并发修正。
- 恶意或损坏 JSON、过大快照、未来 schema 版本。
- 数据库事务失败后的回滚。

### 阶段 3：Zotero 同步适配器

任务：

- 为每台设备查找或创建自己的 PaperPet note，并兼容读取旧版单 note。
- 接入 Zotero 通知和启动扫描。
- 增加防回环哈希和防抖导出队列。
- 记录“本地变更待写入、等待 Zotero、读取其他设备、失败”等状态，不把本机写入当作云端成功。

测试：

- 本机导出后收到自身通知不重复导入。
- 两台设备首次同时离线创建各自 note。
- 网络不可用、note 尚未到达、Zotero 数据同步关闭。
- Zotero 重启、中途关闭、重复通知。

### 阶段 4：设置页和报告 UI

任务：

- 设置页增加同步开关、手动读取、手动写入、本机写入时间、其他设备和会话计数；自动读取已同步到本机的笔记。
- 在报告中按来源筛选，并核对来自两台设备的会话与合计时长；单篇详情显示全部设备的来源。
- 对标题缺失、Zotero 库尚未同步和角色包缺失显示可理解的状态。
- 不增加自动清空本地数据的按钮。

验收：用户关闭同步时，本地阅读和报告继续正常工作；所有破坏性操作都有确认提示。

### 阶段 5：角色包同步（可选后置项）

任务：

- 先同步 pack ID、版本和 manifest 摘要。
- 评估把 `.zpet` 放进 Zotero 存储附件是否会过度占用配额。
- 如果启用，下载到本机后仍走现有安全校验和安装流程。
- 任何本机安装路径只在本地保存，不写入同步快照。

0.5.2 不自动同步角色包；新设备需手动添加 `.zpet` 文件。

### 阶段 6：发布验证

任务：

- 更新 README 的同步说明、隐私边界和故障排查。
- 增加 0.5.2 发布说明和数据库迁移说明。
- 使用隔离输出目录构建 XPI，核验 manifest 和同步脚本标记。
- 在 Zotero 10 Windows 上完成单设备、双设备、断网恢复和 Zotero 数据同步关闭四组手动测试。
- 检查旧版 0.5.1 升级、降级保护和手动备份恢复。

## 3. 建议代码边界

```text
src/sync/sync-types.ts       同步格式、状态和版本
src/sync/zotero-note-carrier.ts Zotero note 读写适配
src/sync/sync-coordinator.ts 防抖队列、通知和生命周期
```

数据库迁移仍由 `src/storage/paperpet-database.ts` 管理；报告只读取重建后的本地表，不直接读取同步 note。阅读识别控制器不应知道云同步细节。

## 4. 风险与应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| Zotero 数据同步未开启 | note 无法到达其他设备 | 不宣称云端成功，保留本地记录和手动备份 |
| 同步 note 过大 | Zotero 拒绝同步 | 约 12,000 编码字符分片、短索引、旧 V2 自动迁移；仍保留本地备份 |
| 两台设备同时修正 | 统计不一致 | 同一 UUID 的会话按更新时间和设备 ID 确定版本 |
| libraryID 不稳定 | 文献无法归属 | 使用 libraryRef，导入时本地映射 |
| 角色包绝对路径不同 | 角色无法加载 | 角色包不参与同步，在新设备重新添加 |
| 导入与本地写入并发 | 数据丢失或重复 | 单写队列、事务、导入前快照 |
| 载体被用户删除 | 同步状态丢失 | 自动发现/重建，绝不删除本地阅读数据 |
| 同步数据含标题 | 隐私暴露 | 启用前提示，不上传正文，并允许关闭 |

## 5. 完成定义

只有以下条件全部满足，才发布 0.5.2：

- 阶段 0 的 Zotero 10 note 载体验证通过。
- 两台隔离配置的离线合并测试通过，且没有重复统计。
- 旧数据库、旧备份和新 schema 迁移测试通过。
- Zotero 数据同步关闭时不显示虚假的云端成功，本地功能不退化。
- 同步失败可重试、可回滚，且不会删除本地记录。
- README、隐私说明、发布说明和 XPI 已同步更新。
- 自动化测试、类型检查、Lint、构建和至少一轮真实 Zotero 10 手动测试通过。
